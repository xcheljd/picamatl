01The idea

Most compressors downsample every image toward a fixed DPI, as if each one filled the page. Picamatl walks each page's content stream tracking the current transformation matrix, so it knows the on-page rendered size of every painted image. From that it computes each image's effective DPI — pixels divided by the inches it actually occupies — and shrinks only what is genuinely over-resolved for how it is displayed.

  • Reused imagesAn image drawn on several pages is sized to its largest placement, so a shared asset is never under-resolved.
  • Both axesEffective DPI is evaluated horizontally and vertically, so a 1000×1000 px image drawn into a 500×100 pt box is caught even when one axis looks fine.
  • Already right-sizedImages at or below the target are left byte-for-byte untouched. No churn, no upscaling, no generation loss.
  • Encoding class keptJPEGs stay JPEG; lossless Flate rasters are downsampled as Flate, so flat-color and line-art content never picks up JPEG ringing.

02The contract

Picamatl is built to sit in a pipeline pointed at input you do not control. The guarantees below are enforced by a panic boundary around the whole pipeline and pinned by regression tests — not by convention.

  • Never largerAny change that cannot prove it shrinks the file is declined. The output is always at most the size of the input.
  • Never corruptMalformed, truncated, or hostile PDFs come back byte-for-byte unchanged. On any error or panic, you get your input.
  • Never onlineZero network requests, by construction — there is nothing in the dependency tree that could make one.
  • Never AGPLPure Rust, MIT or Apache-2.0, no shelled-out Ghostscript, no PostScript interpreter pointed at untrusted bytes.
  • Never silently lossyDefaults are lossless. Accessibility tags, metadata, forms, and the declared PDF version are preserved unless you explicitly opt out.

03Who it's for

  • You embed PDF handling in a product

    You need a permissively licensed compressor without AGPL contamination, a C-library bundling tax, or an upload-to-our-servers privacy policy. Picamatl is a Cargo dependency with a stable API, a hard fail-safe contract, and no runtime dependencies — API docs on docs.rs.

  • You handle sensitive documents

    Client files, legal, medical, financial. “Just upload it to our free tool” has never been an acceptable answer, and picamatl never asks you to: it is a local command that cannot phone home, and it leaves the tags a screen reader needs exactly where it found them.

04Instead of what

How picamatl differs from the usual three options.
Web compressors

Upload your documents to someone else's server, under someone else's retention policy.

Picamatl makes zero network calls. The file never leaves the machine it is on.
Ghostscript

AGPL-3.0 — a licensing landmine inside a product. A PostScript interpreter with a long history of remote-code-execution CVEs via crafted input. Strips the accessibility structure tree.

Picamatl is pure Rust, MIT or Apache-2.0, and keeps the tags. At matched intent on the NASA report it is also 9.8% smaller.
Blind DPI tools

Downsample every image toward one global value, degrading images that were already the right size.

Picamatl reads each image's actual placement and only shrinks what is genuinely over-resolved.

From crates.io

cargo install picamatl

picamatl ~/scans --output-dir ~/small    # batch a whole folder

As a library

// Accessibility-preserving defaults; never panics, never grows the file.
let optimized: Vec<u8> = picamatl::optimize(&input_bytes);

Building from source compiles libjpeg-turbo, which needs NASM and a C compiler at build time. There is no native runtime dependency — the prebuilt binaries need nothing installed at all.

06Honest limits

The things a landing page usually leaves out, stated here because you would find them out anyway:

  • Text-heavy PDFsWith default options picamatl will honestly do very little on a document that is mostly text — and by contract it returns the input unchanged rather than a worse file.
  • Digital signaturesEvery run re-serializes the document, so a /ByteRange digest no longer validates. If a signature must stay valid, do not optimize the file.
  • A PDF 1.5 floorObject-stream packing is on by default. Readers older than Acrobat 6 (2003) cannot open the output; pass --no-pack-object-streams if that is your audience.
  • Not yet handledCCITT and JBIG2 images are left alone. Symbol-mode JBIG2 — the encoding behind the Xerox character-substitution scandal — is permanently out of scope, as a commitment rather than a gap.
